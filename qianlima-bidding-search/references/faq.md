# 常见问题与失败处理

优先按脚本 `user_message/warnings` 说明用户请求是否成功，保留本次业务错误的实际原因。内部错误码、参数和堆栈不直接展示。

| 情况 | 处理 |
| --- | --- |
| 缺少或无效 API Key | 引导 [账号平台](https://ai.qianlima.com/?source=b21e4d10ecdea318b517c48a) 配置或检查，不回显密钥 |
| 正常零结果 | 说明当前条件范围内未找到，不查权益、不编造项目；按普通项目规则决定是否一次加正文补查；明确限制优先，其他扩大按授权处理 |
| 地区权限不足 | 保留地区受限原因；余额足够不证明地区可用 |
| 积分不足或原文月度次数耗尽 | 使用已有的一次诊断补充可用积分或原文剩余次数、重置时间 |
| 网络、结算超时、请求处理中 | 说明本次状态；不自动重复计费调用 |
| 频率限制 | 停止连续提交，建议稍后再试，不推断余额或调用额度 |
| 参数无效 | 原话明确而 Agent 填错字段、枚举、日期或单位时自行修正；只有真实业务歧义才询问，不把错误推给用户 |
| 正文未采集或为空 | 明确本条正文暂不可用，不拿空文本宣称读取成功 |
| 某资源失败、其他资源成功 | 交付成功部分，保留失败原因，不重放成功调用 |
| 状态缺失、过期、损坏或不可写 | 已知 ID 直接读；完整原条件与准确页码用上下文恢复；只澄清缺项，不自动重查。清理/保存失败照常交付 API 成功数据，不重放 |
| 对象有多个候选 | 请用户明确列表/序号/标题，不批量取详情猜测 |

完整错误码见 [API](api.md)。诊断只补充事实，不覆盖原失败；正常零结果、网络、认证和参数错误不触发额外诊断。

## 字段和资源不支持

已知数据源决定可用详情与资源；`detail --id` 默认普通项目，采购意向/临期明确对应 `--result-type`，不从旧名单猜其他来源。源不明只澄清来源。普通项目支持正文、附件、时间线；采购意向仅自身详情中的采购需求和详情页；临期使用自身详情和来源链接。支持检索某位置，不证明详情返回该位置字段。

支持字段返回 null 可说未披露或无法确认；不支持的字段应直接说明能力边界，不假装“未公示”。普通详情中的 `bidingEndTime` 是标书获取截止，`biddingEndTime` 是投标截止。

空结果不建议不存在的普通标讯“不限时间”，不机械将中标通知＋合同放宽为含废标／流标的整个结果类，也不自行删必需概念或扩排除词。

## 外部信息

名称消歧优先 `search-company`；必要外部核验只核实名称。用户明确要求背景分析或接口失败后明确要求 WebSearch，可单独处理公开信息，标注为互联网补充，不替代千里马结果或绕过权限。失败提示不主动引导外部搜索补受限数据。
