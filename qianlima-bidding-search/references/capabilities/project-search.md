# 普通项目与标讯查询

查询公告列表用 `search --query-json '<JSON>' --user-text '<原话>'`，对应 `POST /api/search`。适用于招标机会、结果公示、指定采购单位／中标单位／代理机构的标讯；采购意向、临期续约和企业关系统计走各自能力。

## 最短调用入口

先按本页确定意图与参数；已覆盖所需字段时直接执行，不再通读 API、编译或示例文档。只有缺字段／枚举定义时读 [搜索入参](../api-projects.md#入参字段)，需要单条详情才读 [详情](../api-projects.md#项目详情)。复杂触发条件见 Skill 入口；普通多组 AND 和多个独立筛选不因数量增加预检。

在 Skill 根目录，用户“查500万以上的物业项目”可直接调用：

```bash
python3 scripts/qianlima_skill.py search --query-json '{"keywordGroups":[{"keywords":["物业"],"matchScopes":[2,9]}],"beginAmount":5000000}' --user-text '查500万以上的物业项目'
```

这是一个合法请求样板，不是固定词表。每组两个字段都是数组；按当前意图替换／添加组和本页列明的筛选字段。无需先生成语义计划、试调用或读运行脚本来验证格式；搜索命令自身会校验参数。默认全国、近一个月、全部阶段；泛称招标机会／中标结果按下表另设阶段并说明。

## 先选对象与角色

| 用户目标 | 搜索表达 |
| --- | --- |
| 某医院／学校采购的公告、采购方为某单位的标讯 | 单位完整名称作为关键词，位置 `[4]` |
| 某公司中标项目、中标单位是某公司的公告 | 单位组 `[5]`，泛称中标结果选中标通知＋合同 |
| 某代理机构代理的项目、代理为某机构的标讯 | 单位组 `[6]`；不混成采购方、不自动加机会阶段 |
| 某单位采购／中标／代理的空调项目 | 单位组按角色选 4／5／6；空调另设业务组，组间 AND |

单位名可独立检索，无需产品词或公司 ID；名称中的地名不自动变成项目地区。大学、医院等泛指采购方机构类别时，用 `purchasingUnitTypes` 初筛并核实细分身份；不是要求采购方名称包含“大学／医院”。缺类型枚举值就查枚举，不能为少读文档改用类别字面词。文本提及不证明角色，投标方不等于中标方。“某单位的数据”先结合上下文判断目标／角色，不明确才问；资料、合作统计、公司候选才走企业能力。

## 从业务话到关键词组

按“目标对象 → 必要关系 → 各组位置 → 待核实条件”的顺序判断，再生成参数。每个必要条件必须落到接口条件、具体候选核实或必要澄清之一；不把用户背景、展示格式、通知动作当检索词。结构化字段能准确表达的条件优先用字段。没有有效词及可继承条件时才补问。

`keywordGroups` 必填且非空；每组 `keywords` 非空、组内 OR，组间 AND，各组 `matchScopes` 独立。API 不会对单个字符串分词。按下表由上到下确定粒度，不按词长切分：

| 判断 | 默认做法与边界 |
| --- | --- |
| 明确要求字面匹配，或完整名称、编号、电话 | 原样保留；不从单位名拆出地区，不把业务编号当公告 ID |
| 有独立业务意义的专业概念 | 保留最小完整概念，如劳务派遣、人事外包、会议系统、消毒供应中心；不拆成泛义散词 |
| 完整概念加独立对象／动作 | 拆出必要概念，如消毒供应中心 AND 设备、空调 AND 安装、经营者 AND 招募，避免额外要求词序与相邻 |
| 备选类别或打包采购 | “派遣和外包都看”通常 OR；“供货和安装都包含”用 AND，另核实同一采购范围／标包；不凭“和、都”机械选 AND |
| 共享修饰语、复合服务 | “宿舍管理与保洁”默认宿舍管理 AND 保洁，并核实两项服务均面向宿舍；不要求重复出现宿舍保洁，也不先拆成宿舍／管理／保洁。呼叫中心坐席人员外包默认呼叫中心 AND 坐席人员 AND 外包，核实外包对象 |
| 陌生复合概念 | 保留能可靠识别的业务概念；有歧义且影响目标才问。需要放宽时提出具体拆法与噪声代价，不无依据换粒度 |

这些是初筛默认，结果证据支持时可调整并复用。`(空调 OR 新风) AND 安装` 可一次查询；同位置词组的嵌套逻辑能等价编译时也一次查询。“大学采购实验台，或医院采购通风柜”分别查两条完整配对分支；不同位置的 OR 也分别查，不能压成词与位置的交叉组合，执行见 [查询策略](query-strategy.md)。

### 同义扩展与拆词分开

拆出原话已有概念、整理并列／共享关系，不等于新增词汇。“维保→维护保养”等主动扩展须先展示原词、拟增词及 OR／AND 关系，确认后才搜索；等待时不先查原词。原词保留，确认的同义词加入同一 OR 组；相关、上下位词不自动当同义词。用户明确列出的备选、已知枚举别名直接使用；已确认且含义与逻辑未改的扩展可复用，新增词或改逻辑重新确认。不为让不同说法生成相同字符串而偷偷替换原词。

## 每组位置由概念作用决定

优先级：**用户明确要求 → 当前已确认条件 → 概念作用 → 普通业务默认**。不要给所有组套同一位置。

| 概念作用 | 位置与取舍 |
| --- | --- |
| 普通业务／产品／服务主题 | `[2,9]` 标题＋标的物，平衡起点；“要精准”不自动等于仅标题 |
| 指定采购方／中标方／代理 | `[4]`／`[5]`／`[6]`；全文提及不证明角色，业务组扩围不改变单位组 |
| 编号／电话定位 | 通常 `[8,10]` 正文＋附件，保留完整字符串、优先召回；明确编号字段用 `[3]` |
| 明确联系人字段 | `[7]`；不改成电话有无筛选 |
| 用途、资格或服务对象 | 明确正文／附件则用 `[8]`／`[10]`；未指定位置且有可靠原词时，该组可含正文，如 `[2,9,8]`，另核实关系。无法准确用词／字段表达则留作具体核实，不把整句要求设为连续词 |
| 明确仅标题 | `[2]`，约束用户限定的完整主题；正文不能补齐缺失主题，接受可能漏召回的代价 |
| 明确“全部” | `[1]` 固定是标题＋正文＋附件，其中可有单位、联系人、编号及标的物；不是所有专用索引并集，不默加 `[9]` |

“食品生产企业的冷库维修”中，食品生产企业是采购方行业，不能强制标题出现该字串。无准确字段时以可见单位事实核实，未知标待核实；不能虚构行业字段。“铺位出租，允许开便利超市”中，出租对象与超市用途分组选位置，词命中仍不证明允许经营。

初筛之外的必要条件写清“核实什么、凭什么证据”。优先复用返回内容；证据不足按需取用户所需资源或标待核实，不把候选当已确认，不固定批量读正文、附件或企业高价数据。仅标题要求必须由标题证实，不能用正文兜底。

## 结果不理想时的有限调整

默认执行一个合适方案，不固定跑多个粒度与位置组合。先检查含义、角色、配对及必要条件是否正确，再考虑放宽或收紧。

| 观察 | 下一步及代价 |
| --- | --- |
| 结果少但已满足任务 | 直接交付，不为凑数量补查 |
| 连续短语可能漏掉字序／插词变化 | 建议拆出原有必要概念；覆盖增加，但不同条款的散词也可能命中，仍需核实关系 |
| 主题线索主要在正文 | 仅适用业务组加入正文；增加覆盖，也增加背景或附带条款提及 |
| 散词多、结果偏杂 | 恢复有辨识度的概念或核实业务关系；不删必要概念、不擅改 AND/OR、不自动增排除词 |
| 用户明确尽量查全并覆盖附件 | 适用业务组可用 `[2,9,8,10]`；间接提及和核实成本增加 |

业务／产品／行业首查成功且 `rowCount/total_count` 少于 100，补查有助于目标、又不违背明确位置时，可给适用业务组加正文补查一次。看符合条件总数而非本页条数，错误或未知不当 0；少量已够则不补，编号／号码定位不适用。保留词、逻辑、角色与其他筛选；已有正文不重复，该授权不包含自动拆词、加附件或扩词。明确“仅标题”“无结果才加正文”等要求优先。

自动补查仍是 `/api/search`，不是逐条获取正文；总数用最终响应，不累加。只为比较策略时一次改一个主要因素；用户明确一次改多个条件则一并执行。会改变业务范围、增加同义词或违背明确限制时先确认；清楚的普通拆词不另设确认。

结果用业务话简述实际词组、位置、重要筛选、总数与本批数量；根据可见证据给最有用的 1—2 个精准／召回建议及代价。不把页内观感称为全量精准率或召回率。

## 调用前自检与后续复用

对照实际参数快速核对：**条件有承接；粒度不额外锁字序或丢修饰关系；OR／AND 与配对正确；各组位置正确；待核实条件有标准；本轮未改内容完整保留。** 这在当前判断中完成，不新增固定模型调用或用户确认；预检按 Skill 入口的逻辑风险触发。只有粒度、用途、配对难判时查 [成对案例](../nl_parsing_examples.md#关键词与位置)。

追问／每日任务复用有效词组、位置和核实规则，只修改明确变化；仅改日期、地区或金额不重新拆词。调用方支持保存任务配置时保存完整有效方案，运行时仅更新相对时间等应变值；任务配置与临时结果会话分开。缺前文不猜原词组或已确认扩展，澄清受影响部分；状态失效按 [连续追问](follow-up-and-results.md) 检查完整上下文能否恢复，不擅自重查。

## 结构化筛选与业务口径

下表足以表达时直接调用；未列出的字段细节读 [搜索入参](../api-projects.md#入参字段)，缺具体枚举值读 [枚举](../enums.md)，仅复杂编译读 [查询策略](query-strategy.md#何时预检)。

| 条件 | 业务规则（具体枚举与边界见 API） |
| --- | --- |
| 阶段 `infoTypes` | 无其他上下文的招标机会→`{"0":[3,4],"1":[2]}`，说明招标公告＋重新招标＋预告；泛称中标／成交→`{"3":[11,12]}`，说明中标通知＋合同。明确阶段优先；父类 3 含废标、流标、开标、候选人等，不等于正式中标，阶段不证明可报名 |
| 地区／单位类型 | `areaIds` 为项目所在地，新查询未指定为全国；按 [地区规则](../../SKILL.md#地区) 确认支持后精确查区县；零结果扩市需用户同意。`purchasingUnitTypes` 为采购方类型，非供应商类型，不能替代指定单位名 |
| 发布时间 | `beginTime/endTime` 北京时间；日期补全天，两端包含；仅一端补一个月，均不传近一个月。“今年以来”等完整语义传双端。不支持不限时间；双端无最大跨度，长跨度较慢，引导合适时段但不擅自缩短或拆多次 |
| 金额 | `beginAmount/endAmount` 单位元，500 万→5000000。始终是预算 OR 中标金额任一满足整个范围；阶段不切换字段，未指定阶段时一次搜索。日常按体量，不能因出现“中标金额”就追加严格筛选 |
| 分类／方式／资金 | `procurementCategories/procurementMethods/fundsSources` 内部 OR、彼此 AND，保留指定配对；不凭产品猜分类、凭单位猜资金。采购方式不决定阶段；公开 `[0]`，谈判／磋商 `[2]`，询价 `[4]`，枚举别名无需扩词确认 |
| 报名、有无属性 | `registrationStatus=0` 为时间有值且未结束，空值不匹配；仅未结束不保证已开始、投标未截止或具备资格。`hasBiddingPhone/hasWinningPhone/hasAnnex/hasAgency`：1 有、0 无、不传不限；采购电话不含仅代理电话，有代理不证明有代理电话，不触发资源批量获取 |
| 排除 | 先区分阶段／属性／业务类别／字面词；准确的结构化字段优先，不见“不要”就填排除词 |

金额名称如实展示，预算达标也可纳入日常体量查询。仅明确“实际中标达标、预算不算”或精确成交统计，才核对指定字段；缺失不作 0、不混算预算，优先用返回数据，不批量付费补全。二次筛选区分接口总数与本批确认数，保持对象关联；无依据不保证金额边界含等号或最早历史覆盖。

`excludeWords` 最多 10 个，任一词在任一可搜索位置命中便全局剔除整条，不只作用于正向位置。不能表达仅标题排除或业务分类；全文排除维修可能误删含免费维修条款的采购。不得自行加／换词；可建议更具体词及误删、漏排代价，用户选择后用。不默认批量读正文分类。

## 排序、翻页与后续接口

`sortType` 最新 1、最相关 6、默认综合 2。综合与时间排序同集合同分页：时间倒序分页后，页内依标题正文均完整包含、仅标题完整、仅正文完整、均不完整重排；覆盖越完整越靠前。不把 OR 改 AND、不剔除合法命中，不称全量相关性排名或强拼连续短语。

页码从 1 起，默认 30、最多 100。翻页保持条件与数量；改条件／排序／数量回第一页。公告总数不是去重项目数。无附件为 0、不限为取消，其他未改条件继承；见 [连续追问](follow-up-and-results.md)。

修改关键词时，直接 refine 的 `keywordGroups` 或显式 `keyword_group` 计划都是完整分组替换，须从当前 effective_query 重建整组，保留未改的单位角色、位置和其他概念。通用 `keyword` 语义细化只能替换唯一可定位的业务组并继承旧位置；修改多个业务组或角色／标题／编号时，也须从当前组重建完整 `keywordGroups`；待改对象明确且逻辑不变即可直接 refine，仅触发复杂规则时才改用 `keyword_group` 计划。不猜删旧组，不让用户填写内部参数。

已定位对象：结构化联系人／金额／日期用详情；具体需求、资格、条款或原因用正文；文件与下载用附件；后续公告用进展。已有信息足以回答时复用，不固定串行调用。路径 ID 来自唯一搜索记录或节点，不是业务编号。命令见 [项目资源](../api-project-resources.md)。
