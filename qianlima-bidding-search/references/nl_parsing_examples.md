# 自然语言映射

字段详细定义见各 API reference，条件组合见 [查询策略](capabilities/query-strategy.md)。用户回答使用中文任务用语，不展示内部 ID。

## 时间与金额

以运行当天为今天；普通新查询未指定时间默认近一个月并说明，明确不限时间须确定具体时段，不能省略参数冒充全部历史。

| 用户表达 | 映射 |
| --- | --- |
| 近一周公告 | 含今天共 7 天，发布时间从前 6 天到今天 |
| 近 N 个月公告 | 从今天向前 N 个自然月的同日到今天 |
| 今天、昨天、上个月 | 对应完整日期边界 |
| 9 月 1 日 09:30 至 10:15 公告 | 普通项目使用合法完整秒级 beginTime/endTime，保留时刻 |
| 自某日以来、截至今天 | 按原意明确起点至今天的双端范围；不把“以来”缩成起点之后一个月 |
| 仅明确一个公告时间端点，无其他隐含边界 | 普通项目按接口前后一个月规则补齐，日期和秒级均可 |
| 未来三个月采购意向 | startPlanPurchaseDate/endPlanPurchaseDate，YYYY-MM，从下月起 |
| 最近发布的采购意向 | beginTime/endTime，YYYY-MM，不用预计采购月份替代 |
| 未来半年合同到期 | beginServiceExpireTime/endServiceExpireTime，YYYY-MM-DD 成对完整日期，不传公告时间 |
| 500 万以上 | 元 5000000；项目 beginAmount，意向 startPlanPurchaseAmount，临期 beginContractAmount |
| 200 元以上 | 元 200，核对原话后保留，不强行抬到 10000 |

普通项目金额按预算或中标任一满足的体量筛选，不因金额名词机械追加严格筛选。时间和金额逆序不自动交换；未定义的区间不猜测。普通项目日期起止补 00:00:00/23:59:59，其他源不继承单端秒级能力。

## 关键词与位置

**按需看案例，决策规则只维护在 [普通项目](capabilities/project-search.md)。** 下表 `词@位置` 代表一个 `keywordGroups` 组，括号内 OR 为组内备选，AND 为组间同时满足；这是阅读记法，不是 API 字符串。均保留用户实际日期、地区与阶段，未写出的条件不代表取消。

| 原话／等价表达 | 初筛词组与最终判据 | 近似错误及取舍 |
| --- | --- | --- |
| ① 空调安装／安装空调；空调或新风均要安装／安装空调或安装新风 | `空调@[2,9] AND 安装@[2,9]`；有备选则 `(空调 OR 新风)@[2,9] AND 安装@[2,9]` | 整串空调安装限制相邻；三词同一 OR 组会放过只有安装的项目。AND 命中仍需属于目标采购 |
| ② 消毒供应中心设备／消毒供应中心用的设备；招募超市经营者／超市经营者招募 | `消毒供应中心@[2,9] AND 设备@[2,9]`；`超市@[2,9] AND 经营者@[2,9] AND 招募@[2,9]` | 不要求消毒供应中心设备／经营者招募连续出现；不把消毒供应中心拆碎。若用户明确“字面包含经营者招募”，保留整串 |
| ③ 人事外包和劳务派遣都看／两类机会都要；音视频设备供货安装调试必须打包 | 两类任选为 `(人事外包 OR 劳务派遣)@[2,9]`；打包为音视频设备、供货、安装、调试各一组 `[2,9]`，核实同一采购范围／标包 | “都看”不是都必须出现；打包也不能仅凭词同时出现判满足。未知列待核实，不自动逐条取正文 |
| ④ 宿舍管理与保洁／宿舍的管理和保洁一起采购；呼叫中心坐席人员外包 | 默认宿舍管理 AND 保洁，各 `[2,9]`，核实两项都服务于宿舍；后一例呼叫中心 AND 坐席人员 AND 外包，各 `[2,9]`，核实外包对象 | 宿舍管理 AND 宿舍保洁会要求重复修饰语；三散词可能混入施工管理。若需覆盖“宿舍综合管理”可建议再拆，代价是核实更多候选 |
| ⑤ 北京大学采购的图书／采购方北京大学、内容图书；正文提到北京大学即可 | 前者 `北京大学@[4] AND 图书@[2,9]`；后者按原话 `北京大学@[8]` | 指定角色不等于提到名称；中标方／代理改用 `[5]`／`[6]`。单查指定单位不强加产品词，名称中的北京不是地区条件 |
| ⑥ 食品生产企业的冷库维修／买方做食品生产，找它们冷库维修的项目 | `冷库@[2,9] AND 维修@[2,9]`；以可见采购方事实核实食品生产行业，无证据待核实 | 不把食品生产企业设为标题必含词，也不虚构行业字段；不能仅用名称猜行业或自动批量查企业资料 |
| ⑦ 铺位出租，允许开便利超市／可经营便利超市的出租铺位 | `铺位@[2,9] AND 出租@[2,9] AND 便利超市@[2,9,8]`；核实条款确实允许该用途 | 用途只限标题容易漏；正文“禁止便利超市”也会命中词，必须核实允许关系。用户明确用途只在正文则该组 `[8]`；不要自动加入超市等新词 |
| ⑧ 大学买实验台，或医院买通风柜／这两种配对任一种；标题空调或正文安装 | 两个完整查询：大学（采购方类型）＋实验台；医院（采购方类型）＋通风柜。位置另例分别查 `空调@[2]` 与 `安装@[8]`，共有条件各自保留 | 不压成大学／医院与实验台／通风柜交叉组合；不做 `(空调 OR 安装)@[2,8]`。大学／医院是类型，不强制买方名称字面出现；明确需求不因要分两次而停查 |
| ⑨ 只认标题里的超市经营者招募／标题必须体现招募超市经营者 | 超市、经营者、招募各组 `[2]`；必要主题都由标题证明 | 只搜超市可作宽候选，但必须逐条由标题核实剩余主题；正文不能补成标题达标。少于 100 也不自动扩位置 |
| ⑩ 全部内容找会议系统；只在编号字段找 TEST-2026-007；用电话 010-00000000 找；联系人字段张某 | 分别 `会议系统@[1]`、`TEST-2026-007@[3]`、`010-00000000@[8,10]`、`张某@[7]` | 全部不变成所有索引；编号号码不拆分、不是公告 ID；普通编号定位未限定字段时通常 `[8,10]` |
| ⑪ 查维保，要不要把维护保养也算上；全文不能出现维修／不要维修类项目 | 若提出扩展，先展示维保与维护保养同组 OR，确认后查；明确全文禁词用 `excludeWords=[维修]`；业务类别排除用准确字段或明确核实 | 确认前不查扩词或原词；业务排除不自动等同全局禁词。可建议减少误删的词，用户选择后使用 |
| ⑫ 当前采购方甲医院 `[4]`＋`(空调 OR 新风)@[2,9]`＋安装 `[2,9]`，追问只改日期／把空调换热泵／业务加正文 | 改日期保留全部组；换词只变 OR 组为热泵／新风；加正文只改业务组，角色仍 `[4]`。每日沿用有效方案、更新相对时间 | 完整分组替换不能丢采购方、新风或安装；“便利店也纳入”但旧词组丢失时先澄清，不能假设原词是超市 |

上述小范围粒度示例帮助固定起点，不是行业词库，也不保证覆盖所有表达。比较同义说法时先确认词汇边界：未确认“维保／维护保养”为可互换词，不强求两句生成相同词串。

## 其他常见筛选

| 表达 | 映射 |
| --- | --- |
| 查空调招标机会／找空调招标项目（无其他上下文） | 空调组 `[2,9]`，阶段 `{"0":[3,4],"1":[2]}` |
| 空调中标结果／空调成交结果 | 空调组 `[2,9]`，阶段 `{"3":[11,12]}`，说明中标通知＋合同 |
| 竞争性谈判／竞争性磋商；询价 | 采购方式 `[2]`；询价 `[4]`，枚举别名不需同义扩展确认 |
| 报名没截止／报名时间未结束 | `registrationStatus=0`，报名时间有值且未结束 |
| 标的物空调／附件空调 | 该组位置 `[9]`／`[10]` |

地区、单位类型、阶段、分类、方式、资金不混入业务词。单位类型按采购方类型枚举，不筛供应商类型。0 表示其他分类、公开方式或二值否时都是有效值，取消该条件才用 null。

## 单条信息

已知真实公告 ID 直接 `detail --id ID`；默认普通项目，意向/临期显式 `--result-type`，字段按对应源。序号/标题才从明确结果唯一定位并带 `--result-set-id RESULT --project-ref '第2条'`；用户不填写编号。

| 追问 | 路由 |
| --- | --- |
| 联系人 | 按明确角色、上下文角色，再到采购方默认；采购方字段 purchasingUnitLinkName,purchasingUnitLinkPhone，缺失不替换其他角色 |
| 投标截止 | biddingEndTime |
| 标书获取开始/截止 | bidingAcquireTime/bidingEndTime，不混用投标截止拼写 |
| 报名/投标开始 | registrationBeginTime/tenderBeginTime |
| 项目编号、分类、方式 | xmNumber/threeLevelClassification/zhaoBiaoType |
| 第二第三候选人 | biddingCandidates，ranking/providerName/amount；不是全量投标人 |
| 完整正文、附件、进展 | 普通项目 full-text/attachments/timeline 独立资源 |
| 来源链接 | 普通或临期 detail fields sourceUrl |
| 采购意向的需求 | purchase detail 的 purchaseContent，无普通资源能力 |
| 找某品牌相关公司 | search-company 选择公司主体；明确请求企业分析后才进入 enterprise，只传 companyName |

## 最小必要澄清

缺少有效关键词、地区有歧义、对象/企业主体不唯一、金额或时间冲突、角色与全量参标意图不明时再问；已明确的逻辑无法合成一次查询时分支执行。公司全称、机构名或业务编号可作为有效关键词，不强制补产品词；已确认企业和结果复用。明确原查询可跨会话/Key引用；状态不可用但源、完整有效条件与精确页码已知时用 `--context-json` 恢复，否则只澄清缺项，不自动重查或猜页。
