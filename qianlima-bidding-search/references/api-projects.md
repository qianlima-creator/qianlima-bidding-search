# 普通项目信息接口

## 搜索项目

`POST /api/search`

用于业务主题、公告阶段及指定单位的标讯列表。采购单位／中标单位／代理机构通过关键词组位置 4／5／6 查询，完整单位名可单独作为有效关键词；不需公司 ID。意图、分词与位置策略先读 [普通项目](capabilities/project-search.md)。

### 入参字段

- `keywordGroups`：关键词组列表，必填，至少包含一个有效关键词组。每组都必须包含 `keywords` 和 `matchScopes`。
- `excludeWords`：排除词数组，最多 10 个；任一词在任一可搜索位置命中就排除公告。先区分字面排除与业务类别／阶段排除；能准确用结构化筛选则优先。不得自行扩展或替换用户排除词。
- `currentPage`：页码，可选，从 1 开始，默认 1。
- `numPerPage`：每页数量，可选，默认 30，最大 100。
- `areaIds`：项目所在地的地区 ID 数组，可选；不是采购方／中标方／代理机构所在地。支持省、市、区/县，取值来自 `area.json`，优先用 `area` 命令解析；不传时按全国查询。 先按 [地区规则](../SKILL.md#地区) 取得已确定参数；`[]` 为显式取消筛选，运行时移除该字段，未知编号、布尔值与小数不接受。
- `beginTime`：开始时间，支持 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss`。仅传日期时按当天 `00:00:00` 处理。只传 `beginTime` 时，`endTime` 自动补为开始时间后一个月；如果传入的是日期，自动补齐结束日的 `23:59:59`。
- `endTime`：结束时间，支持 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss`。仅传日期时按当天 `23:59:59` 处理。只传 `endTime` 时，`beginTime` 自动补为结束时间前一个月；如果传入的是日期，自动补齐开始日的 `00:00:00`。
- `beginTime` 和 `endTime` 都不传时，交由接口按近一个月默认范围处理；后续翻页仍省略时间参数。用户明确要求固定日期范围时，首次查询传入双端；开始、结束时间边界均包含。
- 普通标讯不支持不限时间；明确双端时无单次最大跨度，较长跨度查询通常较慢。按需求确定具体范围，不擅自缩短或设置任意历史起点。
- `beginTime/endTime` 非空时必须是有效日期时间，例如不能传 `not-a-date`、`2026-02-30` 或 `2026-09-01 25:00:00`；校验失败返回 `10004`，不会执行搜索。
- `purchasingUnitTypes`：采购方类型数组（不用于供应商类型），枚举见 [枚举](enums.md)。选择一级单位类型时，会同时匹配该类型下的相关单位。
- `infoTypes`：项目阶段映射，例如 `{1:[2], 0:[3]}`，枚举见 [枚举](enums.md)。采购意向不属于标讯项目阶段，不要传 `99`，应使用独立的 `/search/purchase` 接口。
- `infoTypes` 的业务默认：泛称招标机会为 `{"0":[3,4],"1":[2]}`，泛称中标／成交结果为 `{"3":[11,12]}`；父类 3 实际是含流标／废标等的结果公示。明确阶段优先于默认；普通全部阶段省略此字段。
- `sortType`：排序字段，可选。项目搜索支持 `1`（时间倒序）、`2`（综合排序）、`6`（相关性倒序），默认值为 `2`。
- `procurementCategories`：采购分类列表，可选。`0`=其他、`1`=货物、`2`=工程、`3`=服务。
- `procurementMethods`：招标或采购方式列表，可选。`0`=公开招标、`1`=邀请招标、`2`=谈判或磋商、`3`=单一来源、`4`=询价、`5`=其他、`6`=电子卖场。“竞争性谈判”与“竞争性磋商”均映射 `2`，属于枚举别名，不需关键词扩展确认。
- `fundsSources`：资金来源列表，可选。`1`=财政资金、`2`=专项资金及债券、`3`=银行贷款、`4`=投资/融资、`5`=单位自筹。
- `hasAnnex`：附件要求，可选。不传表示不限，`1` 表示只查询有附件项目，`0` 表示只查询无附件项目。
- `hasAgency`：是否有代理机构，可选。`1`有、`0`无、不传不限；有代理不等于有代理电话。
- `registrationStatus`：报名时间是否结束，可选。`1`=报名时间已结束，`0`=报名时间字段有值且未结束，空时间不匹配；不保证已经开始报名，不代表投标未截止或具备资格。不传表示不限。
- `hasBiddingPhone`：是否有采购方／招标单位联系电话，可选。`1`有、`0`无、不传不限；只有代理机构电话不能满足该条件。
- `hasWinningPhone`：是否有中标单位电话，可选。`1`有、`0`无、不传不限；角色不能用其他单位电话替代。
- `beginAmount`：金额下限，单位为元。
- `endAmount`：金额上限，单位为元。

分类、方式、资金来源均为字段内多值 OR、字段之间 AND；指定配对不能压平为交叉多选。未表达这些条件时不凭产品词或采购方身份猜分类、方式、资金。

金额筛选始终为预算或中标金额任一满足整个范围，公告阶段不会切换字段。日常金额按体量处理，仅出现某金额名称不额外二次筛选；明确要求实际中标达标或精确统计时才核对对应字段。万元、亿元换算为元；金额边界是否包含等号无已知保证。

综合排序与时间排序同集合、同分页：先时间倒序分页，综合再在页内优先标题及正文都完整包含、仅标题完整、仅正文完整、均不完整；查询词覆盖越完整页内越靠前，不改变筛选逻辑，不是全量相关性排序。

`keywordGroups` 中每个关键词组包含：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keywords` | string[] | 是 | 当前组至少一个非空关键词；API 不对单个字符串分词，Agent 按业务概念拆解；组内任一词命中即可。 |
| `matchScopes` | integer[] | 是 | 当前组的匹配位置，至少包含一个合法值；`1`=全部（标题+正文+附件）、`2`=标题、`3`=项目编号、`4`=采购单位、`5`=中标单位、`6`=代理机构、`7`=联系人、`8`=正文、`9`=标的物、`10`=附件。没有默认值。 |

普通标讯搜索仅接受上述请求字段，不支持顶层 `keywords`、`keywordsSearchType`、`matchScopes` 和单值
`procurementMethod`。传入未列出的字段或关键词组字段时返回 `10004`。

### 关键词匹配规则

关键词关系要按用户语义判断，而不是等待用户说出技术化的匹配方式。

- 同一个关键词组内固定使用 OR：任一关键词在该组任一指定位置命中即可。
- 不同关键词组之间固定使用 AND：每个关键词组都必须命中。
- 每个关键词组独立指定 `matchScopes`，不要把一个组的匹配位置复用于其他组。
- `excludeWords` 是全局排除条件；任一排除词在任一可搜索位置命中时剔除该项目。
- 用户明确任选的词放同组、必须共同成立的概念拆多组；例如“空调或新风，均需安装”是 `[空调,新风]` 与 `[安装]` 两组。主动新增同义名称先展示方案，得到确认后才搜索；不把空调与新风当作通用同义词。
- 位置 `1` 搜标题、正文、附件；其中可以包含单位、联系人、编号、标的物文本，但文本提及不证明单位角色。业务词通常 `[2,9]`，编号／电话号码通常 `[8,10]`，明确位置优先。
- 当用户表达的是机构类型、地区、阶段、金额、采购分类、采购方式或附件要求时，不要把这些内容混入关键词，应映射到对应结构化字段。

### 查询示例

下例的所有备选词、位置、排除和筛选均来自用户明确选择，不作为默认模板：

```json
{
  "keywordGroups": [
    {
      "keywords": ["空调", "新风"],
      "matchScopes": [2, 9]
    },
    {
      "keywords": ["安装", "改造"],
      "matchScopes": [2, 8, 10]
    }
  ],
  "excludeWords": ["维修"],
  "currentPage": 1,
  "numPerPage": 10,
  "areaIds": [2],
  "infoTypes": {"0": []},
  "procurementCategories": [1],
  "procurementMethods": [0, 2],
  "fundsSources": [1, 2],
  "hasAnnex": 1
}
```

```json
{
  "keywordGroups": [
    {
      "keywords": ["实验室设备"],
      "matchScopes": [2, 9]
    }
  ],
  "currentPage": 1,
  "numPerPage": 30
}
```

上面最后一个示例未传 `beginTime/endTime`，默认查询近一个月。

### 返回字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `rowCount` | integer | 符合当前查询条件的公告总数，非去重项目数。用于告诉用户“共找到多少条”。 |
| `pageCount` | integer | 按当前每页数量计算出的总页数。用于判断是否还有下一批。 |
| `list` | array | 当前页返回的项目卡片列表。为空数组表示当前条件下没有可展示项目，或当前页没有更多项目。 |

项目卡片字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 项目唯一标识。用于后续调用详情接口或原文链接接口，不建议直接展示给普通用户。 |
| `title` | string | 项目名称，也可理解为公告标题。 |
| `purchasingUnit` | string | 招标单位、采购单位或发布项目的单位。 |
| `winningBidderUnit` | string | 中标单位。通常只在中标、合同等结果类项目中有值。 |
| `areaName` | string | 项目所属地区，通常为”省-市-区/县”格式。 |
| `infoType` | string | 项目当前阶段，可能包含一级和二级类型，例如”公告-招标公告””中标结果-中标通知”。面向用户时展示最容易理解的阶段名称。 |
| `budgetAmount` | string | 预算金额，单位为元。为空表示未公示；面向用户时建议转换为万元展示。 |
| `biddingAmount` | string | 中标金额，单位为元。为空表示未公示；只在中标、合同等结果类项目中通常有意义。 |
| `publishTime` | string | 发布时间，格式通常为 `yyyy-MM-dd`。 |
| `hasAnnex` | boolean/null | 是否存在附件。`true` 表示有附件，`false` 表示无附件，无法确认时为 `null`。 |
| `url` | string | 千里马项目详情页链接。面向用户时建议渲染为可点击超链，不展示裸 URL。 |

## 项目详情

`GET /api/detail/{id}`

用于公告的结构化联系人、金额和日期等信息；已有信息足够时复用。已知真实普通公告或时间线节点 ID 直接 `detail --id ID`，无需搜索名单、会话或有效/可写缓存。`--id` 默认普通项目；序号/标题才由对应结果唯一定位，多个候选无法消歧时澄清。业务编号、单位 ID、名称和展示序号不能直接作路径 ID。完整正文、附件和进展按任务选对应接口，详情不是其前置。

详情字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 项目唯一标识。用于确认详情返回的是当前结果中的同一项目，不建议直接展示给普通用户。 |
| `title` | string | 项目名称，也可理解为公告标题。 |
| `xmNumber` | string/null | 项目编号。无法明确唯一对应值时为 `null`。 |
| `threeLevelClassification` | string[]/null | 采购分类；未披露时为 `null`。 |
| `zhaoBiaoType` | string/null | 招标或采购方式，固定归一化为公开招标、邀请招标、谈判或磋商、单一来源、询价、其他、电子卖场之一；未披露或无法归一化时为 `null`。 |
| `areaName` | string | 项目所属地区，通常为“省-市-区/县”格式。 |
| `purchasingUnit` | string | 招标单位、采购单位或发布项目的单位。 |
| `publishTime` | string | 发布时间。 |
| `infoType` | string/null | 项目当前阶段，例如招标公告、中标通知、合同公告等；未披露或无法识别时为 `null`，不影响其他详情字段返回。 |
| `registrationEndTime` | string/null | 报名截止时间；未披露或当前阶段不适用时为 `null`。 |
| `registrationBeginTime` | string/null | 报名开始时间，格式通常为 `yyyy-MM-dd HH:mm:ss`；未披露时为 `null`。 |
| `tenderBeginTime` | string/null | 投标开始时间，格式通常为 `yyyy-MM-dd HH:mm:ss`；未披露时为 `null`。 |
| `bidingAcquireTime` | string/null | 标书获取开始时间，格式通常为 `yyyy-MM-dd HH:mm:ss`；未披露时为 `null`。 |
| `bidingEndTime` | string/null | 标书获取截止时间，格式通常为 `yyyy-MM-dd HH:mm:ss`；未披露时为 `null`。 |
| `biddingEndTime` | string/null | 投标截止时间；未披露或当前阶段不适用时为 `null`。 |
| `openBidingTime` | string/null | 开标日期，格式为 `yyyy-MM-dd HH:mm:ss`；未披露或当前阶段不适用时为 `null`。 |
| `budgetAmount` | string | 招标预算，单位为元。为空表示未公示；面向用户时建议转换为万元展示。 |
| `purchasingUnitLinkName` | string | 招标单位或采购单位联系人。 |
| `purchasingUnitLinkPhone` | string | 招标单位或采购单位联系方式。 |
| `winningBidderUnit` | string | 中标单位。通常只在中标、合同等结果类项目中有值。 |
| `winningBidderUnitLinkName` | string | 中标单位联系人。为空表示未公示。 |
| `winningBidderUnitLinkPhone` | string | 中标单位联系方式。为空表示未公示。 |
| `winningBidderAmount` | string | 中标金额，单位为元。为空表示未公示；面向用户时建议转换为万元展示。 |
| `agencyUnit` | string | 代理机构。 |
| `agencyUnitLinkName` | string | 代理机构联系人。 |
| `agencyUnitLinkPhone` | string | 代理机构联系方式。 |
| `url` | string | 千里马项目详情页链接。面向用户时建议渲染为可点击超链，不展示裸 URL。 |
| `targetKeywords` | array | 标的物关键词列表。面向用户时可称为“标的物”。 |
| `biddingCandidates` | object[] | 排名第二、第三的中标候选人，按候选排名升序；未披露时为空数组。 |

`biddingCandidates` 候选人对象字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ranking` | integer | 候选排名，只返回 `2` 或 `3`。 |
| `providerName` | string | 候选单位名称。 |
| `amount` | number/null | 候选报价，单位为元；公告未披露或无法解析时为 `null`。 |


正文、附件、进展与来源链接见 [项目资源](api-project-resources.md)。`xmNumber` 是业务编号，不能直接作为公告 ID。列表不能证明编号与对象的对应关系时，不批量取详情猜测。详情不包含正文、附件或时间线；候选人只含第二、第三名，不补造第一名。保留数组、0、false 与 null。
